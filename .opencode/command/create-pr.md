Create a Pull Request from the current branch into the target branch.

## Configuration

Target base branch: $ARGUMENTS

If no branch is provided, use `dev`.

## Workflow

1. Load and follow the `@create-pr` skill.
2. Analyze the current branch against the target base branch.
3. Generate the PR title and description according to the skill.
4. Check whether GitHub CLI (`gh`) is installed and authenticated.
5. Verify that the current branch is pushed to the remote repository.
6. Check whether an open PR already exists for the current branch and target base branch.
7. Report the following information to the user:

   - Current branch.
   - Target base branch.
   - Generated PR title.
   - Generated PR description.
   - Whether the branch needs to be pushed.

8. Continue without waiting for a reply — this command opens the PR automatically:
   - Push the current branch if necessary.
   - Create the PR using `gh pr create`, following the skill's Publishing section.
9. Return the created PR URL.

## GitHub CLI

Use:

`gh pr create --base <target-branch> --head <current-branch> --title "<title>" --body "<description>"`

Do not use `--fill`, because the title and description are generated by the skill.

## Safety

- Open the PR automatically — do not ask the user for confirmation.
- Push the current branch automatically when it is missing on the remote.
- Never create a duplicate PR — if one already exists for the branch and target base, report its URL and stop.
- Do not modify commits or rewrite Git history.
- Do not merge the PR.
- If GitHub CLI is unavailable or authentication fails, explain the issue and stop.
- If PR creation fails, report the actual error.
